# The `python` dialect

How Nuclear is written in Python, and in the frameworks built on Python. The same Nuclear code is written once and
the transpiler turns it into each language and framework: this dialect only decides HOW the output is written in
Python (templates, names, imports, the standard library), never what the Nuclear code is. Its framework dialect
`fastapi` implements the [backend platform](../../../nuclear-synapsis-framework/platforms/backend/AGENTS.md) of
Synapsis; what that platform is (kinds, decorators, layout) is the platform's, not described here.

Paths in these documents are relative to this folder (`nuclearlang/dialects/python/`). `../../` is the language
project ([its AGENTS.md](../../AGENTS.md)); `../../../` is the root of the tree.

## Stack

- Target: Python 3.12+ typed (PEP 8: 4 spaces, 88 columns, two blank lines; PEP 695 generics; docstrings), checked
  with `pyright --strict`.
- The dialect: TOML tables and Mustache-subset templates, read at run time by `../../crates/nuclear-dialect`.
- `fastapi` (platform `backend`): FastAPI, SQLAlchemy 2 async, pydantic, LangChain / LangGraph, Alembic, pytest. Its
  runtime is the platform's package `synapsis-py` (import name `synapsis`).
- Type definitions: `python@3.14` and 18 packages of the `fastapi` dialect, generated by `../../tools/defs/python/`
  from the virtual environment `../../tools/python/.venv`.

## Commands

```sh
# from the root of the tree
cargo test                                     # goldens (tour.py, rick_api, tasks_api), dialect validation, editor docs
UPDATE_GOLDEN=1 cargo test -p nuclear-transpile    # accept a changed output, then review the diff
cargo run -q -p nuclear-cli -- build <file.nuc> --dialect python [-o out.py]
cargo run -q -p nuclear-cli -- dialect check python      # or fastapi
cargo run -q -p nuclear-cli -- spec --dialect fastapi    # the contract: templates, variables, options
nuclear-synapsis-framework/platforms/backend/checks/fastapi-check/check.sh   # pyright --strict, pytest, a live run

# from nuclearlang/
tools/spec-check/check.py dialects/python/docs/07-reference/python.md python python [--fix]
tools/spec-check/check.py dialects/python/docs/07-reference/fastapi.md fastapi python [--fix]
tools/stdlib-check.sh [area...]                # the standard library in TypeScript, Dart and Python: the same output
tools/defs/python/generate.sh                  # regenerate defs/
```

What each check needs and proves: [docs/05-standards/testing.md](docs/05-standards/testing.md).

## Folders

- `dialect.toml`: `[options]`, `[syntax]`, `[types]`, `[operators]`, names, automatic imports, `[project]`.
- `keywords.toml`: Python's reserved words and how each is produced from Nuclear.
- `library.toml`: Nuclear's standard library written in Python (one template per member).
- `docs.toml`: what the editor and `nuclear help <word> --dialect python` show for each header word.
- `templates/`: `result.tpl` (the `Result` runtime of a file), `doc_comment.tpl` (docstrings).
- `frameworks/fastapi/`: the framework dialect (`dialect.toml`, `docs.toml`, `templates/`).
- `defs/<package>/<version>/`: type definitions. Generated.
- `docs/`: the context documentation (map below). `docs/07-reference/` and `docs/08-guides/` are normative and
  user texts, checked by tools and embedded in the `nuclear` binary.

## Rules of this project

- **The `.nuc` never bends to Python.** Names stay Nuclear's `camelCase`; the dialect writes them in `snake_case`
  (ADR-python-0001). The compiler's messages use the Nuclear names.
- **Nothing of Python in Rust.** A need of this target is asked of the compiler as a generic `[options]` key or
  template variable (the language project decides it), never as a case of one language.
- **The library is Nuclear's.** Every member of [the standard library](../../docs/07-reference/library.md) has its
  template in `library.toml`; a Python name (`len`, `append`, `upper`) in Nuclear code, in a reference or in an
  example is a bug.
- **A framework dialect only writes the platform.** A kind, a decorator or a folder is added to the platform's
  contract first, for every dialect of the platform; `frameworks/fastapi/` adds how it is written in Python.
- The generated code passes `pyright --strict`; one library per need, the most used, never two that do the same.
- `docs/07-reference/python.md` and `fastapi.md` hold only final rules and real equivalences (`spec-check`, 0
  problems). Never edit an equivalence by hand: change the dialect, then `--fix` and review.
- Every kind, decorator and header word has its entry in `docs.toml` (test `every_dialect_word_has_editor_docs`).
- `defs/` is generated: never edited. After a version or a runtime API changes, regenerate it
  ([runbook](docs/06-runbooks/type-definitions.md)) and update the `defs` lists.
- Output changed: `UPDATE_GOLDEN=1 cargo test`, the diff reviewed, the reference fixed in the same change.
- A structural decision (a library, a pattern of the generated code) is a new ADR in `docs/03-adr/`.
- What is not documented and cannot be read from the dialect files is asked, not invented.
