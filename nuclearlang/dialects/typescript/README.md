# The `typescript` dialect

How Nuclear is written in TypeScript: TypeScript 5 with ES modules that passes `tsc --strict`. Its framework
dialects write two platforms of Synapsis: `react` the [web platform](../../../nuclear-synapsis-framework/platforms/web/AGENTS.md)
and `nestjs` the [backend platform](../../../nuclear-synapsis-framework/platforms/backend/AGENTS.md).

## Why it exists

So that the same Nuclear runs in the browser and on Node.js, written as a TypeScript expert would write it. Names
are written as they are (Nuclear's `camelCase` is TypeScript's); the library is Nuclear's, and each member has its
TypeScript template in `library.toml`, so a TypeScript name such as `push` or `toUpperCase` in Nuclear code is a
bug. A framework dialect leaves out whatever its platform's contract does not have.

## How we made it

- **Nothing of TypeScript in Rust.** What this target needs is a generic `[options]` key or template variable that
  any dialect can use (`relative` imports, `alias_via = "constructor"`, `== null` in operators...), listed by
  `nuclear spec` ([ADR-typescript-0001](docs/03-adr/0001-nestjs-dialect.md)).
- **`react`**: React 19 without JSX, React Router 7, Vite 7, Vitest 4 with Testing Library, over the platform's
  runtime package `synapsis-web`; why React and why without JSX is the web platform's
  [ADR-web-0001](../../../nuclear-synapsis-framework/platforms/web/docs/03-adr/0001-web-platform.md).
- **`nestjs`**: the same Synapsis as the Python backend (ADR-python-0002), on NestJS 12 with ES modules, Sequelize,
  class-validator, kafkajs, ioredis and LangChain.js / LangGraph.js, over the runtime `synapsis-nest`. It extends
  [`nodejs`](../nodejs/AGENTS.md), which is postponed by the user ([ADR-typescript-0001](docs/03-adr/0001-nestjs-dialect.md)).
- **Type definitions** are generated by `../../tools/defs/typescript/` with the TypeScript compiler over the `.d.ts`
  files: TypeScript's standard library and the packages each framework dialect lists (`nuclear defs list --dialect
  react`). The order of `defs` decides which package gives a name two of them export.

It is data only: `dialect.toml`, `keywords.toml`, `library.toml`, `docs.toml`, `templates/`, `frameworks/nestjs/`,
`frameworks/react/` and the generated `defs/`, read at run time by the compiler ([../../](../../README.md)).

## Try it

From the root of the tree (or with the installed `nuclear`). Save as `hello.nuc`:

```
shout(words: string[]) string[]
  words.map(w => w.upper())
```

```sh
cargo run -q -p nuclear-cli -- build hello.nuc --dialect typescript
#   export function shout(words: string[]): string[] {
#     return words.map((w) => w.toUpperCase());
#   }
cargo run -q -p nuclear-cli -- dialect check react         # dialect 'react' (react → typescript) is valid: 16 kinds, ...
cargo run -q -p nuclear-cli -- defs show useState --dialect react   # the hook's API in Nuclear notation
cargo run -q -p nuclear-cli -- spec --brief --dialect react         # the short sheet an agent reads
cd nuclearlang && tools/spec-check/check.py dialects/typescript/docs/07-reference/typescript.md typescript typescript
#   dialects/typescript/docs/07-reference/typescript.md: 29 equivalences, 0 problems
```

A whole web app (`tsc --strict`, vitest, `vite build`):
`nuclear-synapsis-framework/platforms/web/checks/react-check/check.sh`. The website of the tree is one
([../../../website/](../../../website/README.md)).
