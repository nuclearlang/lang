# The `dart` dialect

How Nuclear is written in Dart: Dart 3 that passes `flutter analyze` with `flutter_lints` and no warnings. Its
framework dialect, `flutter`, writes the [mobile platform](../../../nuclear-synapsis-framework/platforms/mobile/AGENTS.md)
of Synapsis: the whole Flutter app is generated from the business logic written in Nuclear.

## Why it exists

A Flutter app is mostly layers, state, JSON and wiring that are always the same. With this dialect Nuclear holds
only the business logic; the layers of a light clean architecture exist in the generated Dart, not in Nuclear.
Names are written as they are (Nuclear's `camelCase` is Dart's) and the library is Nuclear's, translated by
`library.toml`. It leaves out what Flutter already does: the SDK, packages, builds and devices are handled by the
`flutter` command, which `nuclear` drives.

## How we made it

- **`flutter` is a framework that generates the app** over official ecosystem libraries instead of code of our
  own: `bloc` / `flutter_bloc`, `json_serializable`, `get_it`, `dio`, `go_router`, `fpdart` for `Result`; what does
  not exist in Flutter lives in the independent Dart package `synapsis`, usable without Nuclear
  ([ADR-dart-0001](docs/03-adr/0001-flutter-dialect-as-a-framework.md)).
- **The platform says what, the dialect says how.** A kind, a decorator or a folder is added to the platform's
  contract first; `frameworks/flutter/` only writes it in Dart (ADR-dart-0001).
- **Nothing of Dart or Flutter in Rust.** Generic mechanisms (projects, decorators, architecture names) are the
  compiler's; Flutter specifics live here, as data.
- **Imports from type definitions**, not hand-written lists: `dart@3.13.5`, `flutter@3.47.7` and the packages of
  `flutter`, generated by `../../tools/defs/` with `package:analyzer` from the installed Flutter SDK. Every widget
  and class of Flutter and of the Dart libraries can be used, and its import is added by itself.

It is data only: `dialect.toml`, `keywords.toml`, `library.toml`, `docs.toml`, `templates/`, `frameworks/flutter/`
and the generated `defs/`, read at run time by the compiler ([../../](../../README.md)).

## Try it

From the root of the tree (or with the installed `nuclear`). Save as `hello.nuc`:

```
shout(words: string[]) string[]
  words.map(w => w.upper())
```

```sh
cargo run -q -p nuclear-cli -- build hello.nuc --dialect dart
#   List<String> shout(List<String> words) {
#     return words.map((w) => w.toUpperCase()).toList();
#   }
cargo run -q -p nuclear-cli -- dialect check flutter       # dialect 'flutter' (flutter → dart) is valid: 28 kinds, ...
cargo run -q -p nuclear-cli -- defs show Scaffold --dialect flutter   # Flutter's Scaffold in Nuclear notation
cargo run -q -p nuclear-cli -- help tutorial                          # a Flutter app from scratch with Synapsis
cd nuclearlang && tools/spec-check/check.py dialects/dart/docs/07-reference/dart.md dart dart
#   dialects/dart/docs/07-reference/dart.md: 30 equivalences, 0 problems
```

The examples under `flutter analyze`: `nuclear-synapsis-framework/platforms/mobile/checks/analyze-flutter.sh`
(it needs Flutter: `FLUTTER` or `FLUTTER_ROOT` if it is not on the PATH).
