# How code and documents are written in this project

The rules every project shares (English, quality first, Nuclear first, git, when a change is done) are the tree's
[`../docs/05-standards/coding.md`](../../../docs/05-standards/coding.md). These are the language's own.

## The compiler

- **The parser does not change per dialect.** Dialect words arrive as data in a declaration header ("header +
  block"); framework words, shortcuts and imports live in `dialects/`.
- **Rust decides *what* is emitted; the dialect decides *how* it is written.** The transpiler knows no target
  language: TypeScript, Dart and Python are dialects like any other.
- **A target's need is a generic option.** What a template cannot express is added to the emitter as an
  `[options]` option or a template variable any dialect can use, never as a case of one language.
- **The `.nuc` never bends for a dialect.** It keeps Nuclear's naming (camelCase, `docs/07-reference/nuclear-base.md`
  §2.4) and the base syntax; a target's convention is applied to the output (`options.snake_case_names`).
- **Errors over magic:** no inferred parameters, no hoisting, no `type`; explicit beats implicit when in doubt.
- **Each stage knows only the previous one** (lexer → parser → resolver → emitter); every AST node keeps its
  `Span`.
- **The generated text does not change for a tool:** the line map is recorded beside it, not by aligning lines.
- **`ast.rs` and the public API are shared.** A changed variant or signature is announced by the workspace build:
  the language server, `../tools/cli/` and `../tools/code_generator/` walk the AST themselves.
- Rust style: `../rustfmt.toml` (`max_width = 120`, `use_small_heuristics = "Max"`); `cargo clippy --all-targets`
  without warnings.

## Diagnostics

- Codes: N00xx syntax, N01xx resolver, N02xx dialect, N03xx project (`crates/nuclear-diag/src/lib.rs`).
- Every new code is documented in `docs/07-reference/diagnostics.md` (test `every_code_is_documented`).
- A diagnostic gives the Nuclear form and, when the correction is exact, a `fix` the tools can apply.
- A false positive of the habits scan (N0022) is a bug.

## Dialect data

- Every kind, decorator, modifier and clause of a dialect has editor documentation in its `docs.toml` (test
  `every_dialect_word_has_editor_docs`); every reserved word of the base in `base/docs.toml`.
- `dialects/<language>/defs/` is generated by `tools/defs/`: never edited by hand.
- `base/nuclear.toml` lists the only words the lexer reserves; dialect words are not reserved.

## The normative documents (`docs/07-reference/`, `docs/08-guides/`)

- `nuclear-base.md` holds only final rules and only Nuclear: no dialect, no target language, no questions, no
  history, nothing "pending". `library.md` the same for the standard library.
- A dialect's rules go in its own reference (`dialects/<language>/docs/07-reference/<dialect>.md`), which inherits
  the base and holds the Nuclear → target equivalences of the base examples (the few-shot an agent reads). They
  must be the real output: `tools/spec-check/check.py` gives 0 problems.
- A target's library name on a base type (`push`, `len`, `toUpperCase`) in a reference, a guide or an example is a
  bug: the standard library is Nuclear's (ADR-lang-0009).
- Doubts are asked to the user and written in the reference once decided; a decision becomes an ADR.
- New syntax: decide with the user how it is written; then reference + `grammar.ebnf` + parser + emitter +
  contract + tests.
- A new `.md` in these two folders must be a topic of `nuclear help` (`../tools/cli/` embeds them with
  `include_str!`; its test `every_document_is_a_help_topic`). After a change, the installed `nuclear` is installed
  again (`../installer/install.sh`).

## A change of this project is done when

1. `cargo test` and `cargo clippy --all-targets` are green from the root of the tree; generated code changed:
   `UPDATE_GOLDEN=1 cargo test` and the diff reviewed.
2. The references whose equivalences the change touches pass `tools/spec-check/check.py` (the guide too:
   `--fix` rewrites the blocks that differ).
3. The documents say it in the same change: the reference of the area, `docs/02-architecture/`, this project's
   `AGENTS.md` if a command, a folder or a rule changed, an ADR if the user decided something, the roadmap (a done
   item deleted, half-done work recorded when it is left).
4. A change to the language server is released with the editor extensions (`../extensions/`).
