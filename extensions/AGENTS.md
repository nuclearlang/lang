# Editor extensions

The editor tooling of NuclearLang: one extension per editor (VS Code, Android Studio / IntelliJ, Zed) and the tools
they show (Nuclear Builder, HTTP Connections, Nuclear Atlas, Nuclear Monitor, the devices). This folder is the
index of those projects and holds what the three extensions share. The language server is **not** here: it is
`nuclearlang/crates/nuclear-lsp`, part of [the language project](../nuclearlang/AGENTS.md). The extensions run it
as an external binary and talk to it only through LSP and the `nuclear/*` requests.

## Stack
- `vscode/`: TypeScript, esbuild, `vscode-languageclient`; VS Code 1.90 or newer
- `jetbrains/`: Java, compiled with `javac` against the installed IDE (no Gradle); the platform's native LSP API
- `zed/`: Rust → wasm32-wasip2, `zed_extension_api` 0.7, a tree-sitter grammar of tokens
- The platform's one version (ADR-platform-0011, 0.80.0 today), written by `installer/release/version.sh` into
  `vscode/package.json`, `jetbrains/resources/META-INF/plugin.xml`, `zed/extension.toml` and every other project

## Commands
Each extension has its own; they are in its `AGENTS.md`.

- VS Code: `cd vscode && npm run compile` · `npm test` · `npm run package`
- JetBrains: `cd jetbrains && IDE_HOME=/opt/android-studio ./build.sh`
- Zed: `cd zed && ./build.sh` (builds and installs into Zed)
- The server: `cargo test -p nuclear-lsp && cargo clippy --all-targets`, from the tree's root

## Folders
- `vscode/`: the VS Code extension; its `theme/` also generates the themes and icons of the other two
- `jetbrains/`: the Android Studio / IntelliJ plugin
- `zed/`: the Zed extension
- `tools/<tool>/`: one project per tool of the editors, with its code: `src/` (and `test/`), bundled by the VS Code
  extension, and `jetbrains/src/` (Nuclear Builder, HTTP Connections), compiled by the JetBrains `build.sh`
- `docs/`: what is common to the three extensions

## Rules
- A missing feature of the server is built in `nuclearlang/crates/nuclear-lsp`, with the rules of the language
  project.
- Done = `npm run compile` in `vscode/` if the client or a tool's `src/` changed, `npm test` there if Nuclear
  Builder changed, `npm run theme` there if the palette changed, `jetbrains/build.sh` if the plugin or a tool's
  `jetbrains/src/` changed; and the server's tests and clippy if the server changed.
- **Always release after a change** of the server, a client, the themes or the bundled dialects and type
  definitions, without asking: [docs/06-runbooks/release.md](docs/06-runbooks/release.md).
- **Every release keeps what users already have working** (the user, 2026-11-18): before a release, check that
  the data and settings an earlier version wrote still load and behave — team files (v1 `roles` and v2 `members`),
  run files of earlier engines, specs of the flat layout, chat histories, settings moved to new ids, the onboarding's
  state. A change of a stored format converts on read (the old file kept as `.bak`), never fails on it; what cannot
  be converted is told to the user with what to do. The check is in [the release runbook](docs/06-runbooks/release.md)
  ("Backward compatibility") and its fixtures are tested.
- Themes and icons of the three extensions are generated by `vscode/theme/`: edit `palette.json`, `build.mjs` or
  `icons.mjs`, never the generated JSON, XML or SVG.
- Framework extensions must not collide: only the base extension registers the language, the grammar and the
  language server (ADR-extensions-0001).
- Nuclear Builder is for VS Code and Android Studio only (decided by the user): Zed has none.
- A tool's code and documents live in its folder under `tools/`; an extension only wires it in.
