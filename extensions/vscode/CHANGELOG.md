# Changelog

All notable changes to nuclear-vscode are written here; versions follow [Semantic Versioning](https://semver.org).

## Unreleased

- Nuclear Builder: a spec is deleted from the page (*Delete* in the spec's view and in the head of its run when nothing runs), asked first; its folder moves to `.nuclear/builder/deleted/`, nothing is lost.
- HTTP Connections no longer repeats an endpoint: a mobile or web app's call to the window's own backend is that backend's route, shown once with the apps that call it (`api · app, web`); a call to another service (a weather API) stays under the app. The HTTP Connections request tests, never run before, now run with the extension's tests.
- **Nuclear Monitor watches and measures web and mobile apps**: *Measure the app* works for every app; *Run and watch* opens a web app on the web device and a mobile app on the device picked, measured. Their console is the page's (prints, errors with their stack and *Open in the code*, each request with its address and status, a request with no answer with its reason: what was "No connection to the server"), and their measurements arrive through the window's collector (127.0.0.1, a token, the app's origin only). The web device's log has no terminal colours any more; the devices write how a run ended.
- **Nuclear Builder runs a station's checks at the same time**: four at once by default (`parallelChecks` in `.nuclear/builder.json`, 1 to 16), each its own agent's session, step, trace and cost, in its own copy of the project with its fixes merged back; the page shows each with its spinner and *Now · N checks at the same time*, the log in the order they ended (English and Spanish). Six checks of a stubbed second each: 6.1 s before, 2.0 s now.

- ▷ Serve of a backend or web app becomes ■ Stop (in *Actions* and in the editor title) while its `nuclear run` runs, and ■ Stop ends it; ▷ Serve or `Ctrl+Alt+R` on a project that already serves shows its terminal instead of starting a second server.
- Fix: switching between the Devices tool and the workspace deformed the editor: the device's locked group stayed standing when parked, the next device spanned the whole editor, that width was remembered as the user's and the device came back at half. Parked devices now close their groups before the code closes, the Devices tool keeps the device at its width, and only a width chosen beside code is remembered.
- Fix: on a machine whose folder is a Nuclear workspace (its apps in subfolders) the Synapsis device was never registered with Flutter, and a run on it was refused; it is registered at the first run on a device.
- Fix: a file clicked in the workspace's tree opened beside the device instead of in the main editor group: the device locked the user's editor group when the focus was still there. The device's lock now waits until its own group is active, and the tree opens files in the main (leftmost) group, lifting a lock left on it.
- **Nuclear Monitor shows what your app is doing, live, with no command to type**: the strip's *Monitor* opens on the workspace's selected app (it opened on the workspace's folder and showed the raw error "no .nuclear/monitor/report.json in … or above"), switches among its apps, and runs the app when it is not running, visibly in the terminal `<app> · monitor` (a phone app: the device pick), once by itself and then by *Run and watch*. Its **console** holds the last run: every request (method, path, status, time), every error with its cause and its stack (your code's frames stand out; *Open in the code* goes to the `.nuc` line), the app's own lines, the build, reloads and the stop, filtered by *All*, *Requests* and *Errors*. *Measure the app* keeps the app measured through saves and reloads (the accordion of each function's time). Designed states (starting, running without traffic, could not start with *Try again* and *Details*, no project) in English and Spanish; paths and commands only in *Details*. Reports of earlier versions still draw.
- Fix: the workspace's *Actions* list drew each key over its action's name (`Ctrl+Alt+R` over `▷ Serve`): the name comes first and its key at the right, dimmed, as VS Code's menus show it.
- **Every node of a Nuclear Builder run can be retried, smallest first, and a failure never throws the agents' work away**: an agent's call or a command that fails (a timeout, a crash, a broken pipe, a flaky test) is tried again in its step, then the station's part is worked again told what failed, then the station is diagnosed and repaired, and only then the run waits for you (*Retry*, *End as failed*, *Later*) instead of ending failed; every attempt goes on from the files the one before wrote (nothing taken back on a failure, a stop or a crash). A failure no retry can fix (the budget, a missing key, a tool not installed) is asked at once. The bounds are the line's `retries` (`process` 2, `node` 1, `station` 1). By hand: *↻ Retry "<step>"* on the run, *↻* on every step and failed attempt in the node's tree, a station, the whole run (`nuclear-builder retry <id> [--step|--from]`, `run_retry`); each retry is shown as it happens, in English and Spanish, and run files of earlier versions are retried in place too.
- **A failed step of Nuclear Builder is retried alone, and no run loses the agents' work again**: *Retry from the failed step* is the main action of a failed run (every step before it kept, the Developer's code among them), *Retry this step* is in a failed step's detail, and *Start over…* is apart and asks first. Fix: an undo (a failed step, a repair, a retry from a station, a restart) deleted the files the agents wrote with no copy; now each is set aside first in `.nuclear/builder/runs/<run>.set-aside/`, listed under the run. Whatever takes the agents' work back asks first, naming the files and where they are kept: the page's modal (Cancel by default), the terminal (`retry`, `restart` and `spec delete` refuse without `--yes` elsewhere), the tool `run_retry` (`confirm`). Fix: a Builder window that reloads no longer fails the step a run was in (`Broken pipe`).
- Fix: the workspace's file tree shows what an agent or a Builder run writes while it works (a new component did not appear): the column, drawn again many times a second during a run, made a new files watcher each time and dropped the folders it had not sent yet; the watcher now lives as long as its project, and the project's folders are read again whenever watching starts.
- Each notification has a check at its left: done or pending. A run's notification is checked by itself once you answer it; any notification can be marked done, or pending again, with it.
- Fix: the Builder's question card no longer redraws itself every second while a run waits (its buttons flickered and a click could be lost), and its question is in your language (it showed the engine's English).
- Fix: the welcome no longer closes when an app is added from it (adding a third app, web, closed it): the app opens and the welcome stays for the next one.
- Fix: in a workspace's own channel, a message is answered by the tech lead of the team assigned to it (nobody answered: the channel did not name its team).
- **Nuclear Builder shows a run as its progress**: the stations in a line with who works each, what is being done now (or what waits for your answer, with *Answer*), and the spec it works on with its criteria; *Technical diagram* shows the detailed one. A run the team starts from the chat appears by itself: the open Builder moves to it, a notice says so, and opening the Builder shows the run being worked on.
- Fix: a spec and its run asked in a workspace's channel go to the app they are for (the tech lead says which); they went to the workspace's folder, where the Builder never showed them and the code would not have been written in the app.
- Nuclear Atlas opens again on the conversation you were in last, in each folder (also after a restart).
- **Nuclear Atlas's channels and direct messages are in the workspace's column**, as Nuclear Chat draws them: a click opens that conversation in the page, which now shows only the open conversation (the whole chat again when the column is hidden).
- Fix: the welcome adds an app with the name it offers when the field is left empty (it asked for one again), and the offered name follows the platform (shop_api, shop_web, shop_app); the new-team wizard creates no team without a member.

A project opened by hand in 0.84 to 0.88.3 is opened again with *Open a Project as a Tab* in the window that wants it.

- Fix: with the open workspace deleted from the disk, the extension keeps working: the welcome starts again from creating or opening a workspace (it no longer offers to add apps to the deleted one, which made its folder again), *Create* and *Open* work and take the window without asking to keep a folder that is not there, and no command runs in the deleted folder.

Plain words: members, not operatives.

Runs started outside the editor (the MCP server, a terminal) are followed there too.

- **Local first** (spec 023): no page loads anything from the internet (a test scans every page and bundle). If a bundled file is missing (a broken install), the extension says so, takes the same version's files from its GitHub release, checks them (the release's `.sha256`, else the size and the version inside) and keeps them in its storage; *Reload Window* then uses them. Pages that use that copy keep the extension's own folder readable.
