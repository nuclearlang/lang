# Architecture of the app

A web project of Synapsis (`config.nuc`: `synapsis(platform = "web", dialect = "react")`, `app(name =
"nuclearlang_website", ...)`, `dependencies(motion = ...)`) with one component, `components/docs/`: the whole site
is one feature, and its views share the top bar and the site's managers, which a component keeps private (N0302).
It reads only the JSON that [`tools/content.mjs`](content.md) writes into `public/content/`.

```
config/project_config.nuc        Http(baseUrl = "/", timeout = 10000): the site reads its own public/content/
main.nuc                         App: the router with every @screen
defs/typescript/motion/          the type definitions of motion, generated by `nuclear add motion`
components/docs/
  data/                          ContentRepository (pages, site, search, home), ToolRepository (tools.json),
                                 PlatformRepository (platforms.json)
  domain/models/                 Page, Site, SearchEntry, Home, Tool*, Platform*, ContentError, ToolError, PlatformError
  domain/usecases/               GetPage, GetSite, GetHome, Search, ListTools, ListPlatforms
  domain/services/search_score   the ranking of the search
  presentation/home/             HomeScreen "/" and its blocks + HomeManager
  presentation/tools/            ToolsScreen "/tools", ToolScreen "/tools/:name" + ToolsManager
  presentation/platforms/        PlatformsScreen "/platforms", PlatformScreen "/platforms/:name",
                                 StartScreen "/start/:name" (the onboarding) + PlatformsManager
  presentation/doc/              DocScreen "/:area/:name", DocGroupScreen "/:area/:group/:name", NotFoundScreen
  presentation/layout/           Layout (with the side menu), Frame (without), TopBar, Footer, SearchBox, and the
                                 views the pages share: Reveal, CodeTabs, Terminal, Diagram; SiteManager, SearchManager
public/styles.css, favicon.svg   the look: the Chernobyl palette of the editors (dark) and a light theme
test/docs_test.nuc               the search, a page, the home page, a tool, a platform, an onboarding (repositories mocked)
```

The tools' and platforms' models, repositories, use cases, managers and first screens were written by
`nuclear gen resource docs Tool|Platform --source rest --path content/<file>.json --from-json public/content/<file>.json
--actions list --screen <screen>`; the other views by `nuclear make stateful|stateless docs <Name> --screen <screen>`
and then filled. The Home model is written by hand: the generator has no resource of one object.

## The screens

- **The home page** is a column of blocks, each its own view: `Hero`, the hooks, `Samples` (pick a sample, then a
  target; the Nuclear stays beside it), `CheckBlock` (an agent's mistake; "Run nuclear fix" switches to the fixed
  code), `GeneratorBlock` (a `Terminal` that replays the backend onboarding, and its numbers), `DialectsBlock` (one
  file, a tab per dialect), the platforms, the tools, the library, install.
- **A tool** and **a platform** are read from the list their manager loads (`find` by key); an unknown key shows
  "Not found". A platform's page is its `Diagram`s (one per C4 level) and the code level (`CodeTabs`).
- **The onboarding** is a stateful stepper: one step at a time, its real output in a `Terminal`, then the app's code.
- **Motion**: `Reveal` wraps the content once it is loaded and runs `motion` on its blocks
  ([ADR-website-0003](../03-adr/0003-libraries-of-the-target-through-nuclear-add.md)).

## A page of documentation

`GetPageUseCase` turns an address into a content key: the parts of the path joined by `--`
(`/nuclearlang/guide/README` → `content/nuclearlang--guide--README.json`). Every address has three parts, the depth
`DocGroupScreen` (`/:area/:group/:name`) routes; the screens of the tools, the platforms and the onboardings have
static first parts, which the router prefers. The page's HTML comes ready (highlighted at build time): the browser
never parses markdown.

A link between pages reloads the page (the content is cached by the browser); navigation by address inside the app
is pending in the web platform ([its roadmap](../../../nuclear-synapsis-framework/platforms/web/docs/01-product/roadmap.md)).

## Build and test

`nuclear build` writes the app into `build/app` (with `public/` copied), `nuclear install` runs `npm install` there,
`nuclear test` runs vitest over `test/`, `npx vite build` in `build/app` writes the bundle to `build/app/dist`. The
CI (`.github/workflows/website.yml`) installs `nuclear` from the tree and runs the same steps.
