# Changelog

All notable changes to nuclear are written here; versions follow [Semantic Versioning](https://semver.org).

## Unreleased

- **The MCP server is the agents' oracle** (spec 025): Nuclear Builder's agents cost less and take less time for the
  same work. Each tool reaches an agent of the factory once (`nuclear-mcp --skip`: 45 tools instead of 92); OpenCode's
  agents never get the user's own `~/.claude` instructions and skills, nor OpenCode's tools the factory does not use,
  and never read nor change `build/`, `node_modules/` or `dist/`; a step's prompt sends the agent to the oracle first
  and names where each document it already holds is; Anthropic's requests cache their prefix (a cache read priced as
  it is). Measured on one spec with Haiku: -40 % to -43 % tokens in, -49 % time, -60 % files read by hand. The ledger
  and `nuclear-builder metrics --view context` say each step's turns, tool calls and reads by hand. A local model whose
  window is too small (Ollama gives 4 096 tokens under 24 GiB of VRAM) is refused before any call with its fix, and
  Ollama's *the prompt is longer than the context length* is said with the same fix (a `-32k` variant made with
  `PARAMETER num_ctx 32768`). Fix: a run whose agent marked several checks at once tore `checks.json` and the engine
  fell.
- **A project's documents point to the oracle** (spec 025): `nuclear new` writes in `docs/README.md` and `AGENTS.md`
  that Nuclear is asked of the MCP server and never copied into the project, whose documents hold its own architecture
  (its components' layers, where each piece goes), business and decisions; `nuclear agent init` adds the section to a
  project made before.
- **An empty text under `@required` answers the rule `required`** in every backend dialect, never `minLength`
  (ADR-synapsis-0014); `@minLength(1)` still answers `minLength`.

- **Migrating a project into Nuclear** (ADR-platform-0015; the user: "one of the most important features of the ecosystem"): an agent asked to migrate a project of another technology refused, because the rules and the Smart Graph said Nuclear "cannot read TypeScript, Dart or Python". Now the transpiler still reads only `.nuc`, and an agent reads the original as the specification and rewrites it in Nuclear with the tools. New MCP tool `migration_inspect(folder)` (read-only): each app of the original (`package.json`, `pubspec.yaml`, `pyproject.toml`, `requirements.txt`), its language and frameworks, the Nuclear platform and dialect it becomes (React → `web`/`react`; Flutter, React Native → `mobile`/`flutter`; Express, NestJS → `backend`/`nestjs`; FastAPI, Flask, Django → `backend`/`fastapi`), its database plugin and what becomes of each dependency. The graph's new strategy `strategy:migrate-project` is the plan (inventory, workspace, one spec per component, the generators, the rest in Nuclear, the original's tests as the proof), with `can:migrate-a-project`. Express is a source like any other: it is postponed only as a dialect.
- **No agent changes Nuclear; the installation is sealed** (ADR-platform-0016): the installers write `.seal` (size, time and SHA-256 of every file of `bin/`, `dialects/`, `platforms/`, `generators/`) and make those folders read-only; every build and check compares sizes and times (once per process) and refuses a changed installation (**N0226**), `nuclear doctor` compares the hashes. A dialect from outside the installation (a project's `dialects/`, `--dialect-path`, `NUCLEAR_DIALECT_PATH`) with the name of an installed one is refused (**N0225**): before, a folder `dialects/fastapi/` in a project replaced the installed dialect. `nuclear doctor --seal` is the installers' last step. The rule, `cannot:change-nuclear`, is in the skill, `nuclear_start`, the MCP server's instructions and the project's `AGENTS.md`.

- HTTP Connections no longer repeats an endpoint: a mobile or web app's call to the window's own backend is that backend's route, shown once with the apps that call it (`api · app, web`); a call to another service (a weather API) stays under the app. The HTTP Connections request tests, never run before, now run with the extension's tests.
- Fix: a mobile app whose packages an earlier release fetched failed with `Couldn't resolve the package 'decimal'` (the `synapsis` runtime of 0.100 needs it, and `pub get` ran again only when the app's own pubspec changed): `nuclear build` runs `pub get` again when another version of the platform made the last one.
- **Exact numbers in mobile and web apps** (ADR-lang-0015, the backend's rule ADR-backend-0003): a model's `bigint` and `bigdouble` fields are exact in `flutter` (`BigInt`, `Decimal` of `package:decimal`, which `nuclear build` adds to the app's `pubspec.yaml` when the code uses it) and `react` (`bigint`, the dialect's decimal). Their JSON is a text both ways, the language's `toString()` (`"0.3"`, `"2.0"`); an answer whose exact field is a JSON number, another text or more than 1000 digits is a decoding error that fails the call (a `FormatException` on mobile, a `TypeError` on the web), never a rounded value. A client generated from a backend's contract (`contracts(...)`) gets its exact fields, bounds and defaults as `bigint` / `bigdouble`, never `string`; `nuclear gen resource --fields "price:bigdouble"` takes them on both platforms. A mobile local table keeps an exact field's text and its queries compare and sort it by value (`where` with `gt`, `gte`, `lt`, `lte`, `between`, `oneOf`, `ne`, equality, and `orderBy`); a mobile form validates the text of an exact field, and its `@min` / `@max` compare exactly. A route that answers a single exact number is read from its text. The web runtime sends a request's body as its model's `toJson()` (`@key` names were sent as the field's name). A lambda given to a state builder for one of its states takes that state's type (`full = (items) => ...`, the state model in any file), so a `bigdouble` it shows is written `2.0` in every dialect (Dart wrote `2`). Fix: a mobile repository method that answers a `boolean` or another plain value inside a `Result` (a backend's generated `remove`) built Dart that `flutter analyze` refused (`Decode.value` could not infer its type).
- **Exact numbers in mobile and web apps** (ADR-lang-0015, the backend's rule ADR-backend-0003): a model's `bigint` and `bigdouble` fields are exact in `flutter` (`BigInt`, `Decimal` of `package:decimal`, which `nuclear build` adds to the app's `pubspec.yaml` when the code uses it) and `react` (`bigint`, the dialect's decimal). - **Nuclear Monitor for every app: a web app and a mobile app are watched and measured too** (the user: "Monitor for everything"). A measured app in a browser (a `react` app; a `flutter` app on the Synapsis device, which is Flutter web) posts its report every two seconds to a **collector** (the editor's, one per window; `nuclear run --monitor`'s own without the editor) on 127.0.0.1, with a random port, a token and the project's key, taken only from the app's own origin, and written to the project's `.nuclear/monitor/report.json`, so `nuclear monitor --json` stays the only source of hot spots. The address reaches the build as `NUCLEAR_MONITOR_URL` (rebuilds on save keep it). The Dart runtime no longer touches `dart:io` in a browser: its host there is a second generated file, `nuclear/monitor_web.dart` (the dialects' new optional template `monitor_runtime_web`), imported conditionally; the TypeScript runtime posts from its browser branch with the page's own `fetch` (not counted). The **console** of such an app is its page's: the web device writes the page's prints, its errors with their stack and each request to a server into the run log, the Synapsis device the requests (Flutter's output already has the prints and errors): a request with no answer is an error with its reason (`ERROR GET http://127.0.0.1:8000/films net::ERR_CONNECTION_REFUSED`), the cause behind "No connection to the server". `nuclear monitor` reads a browser's requests with their address, a page's errors, and Flutter's web errors with their frames (`DartError: …` was plain output; *Open in the code* now lands on the `.nuc` line). A device that stops ends its run in the log (the Monitor said *Running* after it closed). Not yet: an app on a real phone or an emulator (it cannot reach the editor's 127.0.0.1).
- **Nuclear Builder runs a station's checks at the same time** (a check is an agent's session of minutes, and a station's ran one after another: Design took 17.7 min on the user's run): the checks by prompt of a station run together, at most `parallelChecks` at once (`.nuclear/builder.json`, 4 by default, 1 to 16; 1 is the earlier one after another), each its own session, step, trace, journal line and cost, in its own temporary copy of the project; what each fixes comes back merged (`git merge-file`), a clash set aside and that check run again on the project. The checks by command and those of `parallel = false` (the role's data: the ones that run the project) go one at a time, in the project. Each check starts with its share of what the budget has left, so together they never overspend; with nothing left none starts. A check that fails is retried alone (process, node, the user's retry in place): those that passed stay passed while the work they judged stays. The page shows each with its spinner, *Now · N checks at the same time*, the log and the journal in the order they ended. Measured with stubbed agents of 1 s, six checks: 6.1 s before, 2.0 s with 4 at once. Older run files and check lists load and retry as before.

- **Exact numbers in a backend** (ADR-backend-0003): an entity's `bigint` is a `BIGINT` column and a `bigdouble` a `NUMERIC(p, s)` (`@column(precision = 40, scale = 20)`; 30 and 10 by default), in `fastapi` and `nestjs` on SQLite, PostgreSQL, MySQL and MariaDB, with migrations; SQLite keeps their text and the runtimes compare and sort it by value; a value the column cannot hold is 409, never rounded.
